SCENE 3 — Project landing page (opened from a project card)
-----------------------------------------------------------

┌──────────────────────────────────────────────────────────────────────┐
│  Test                                                       [📌] [⋮] │  ← project name as title
│                                                                        │

│  │                                                                    ││

│  └──────────────────────────────────────────────────────────────────┘│
│                                                                        │
│                                                    Opus 4.8 · High ⌄ │  ← model selector only
│                                                                        │
│                              💬                                       │
│                                                                        │
│       Give Claude a task and it'll pick up your project context.      │
└──────────────────────────────────────────────────────────────────────┘

  Composer has NO project selector and NO "Ask" affordance. The project
  is implicit — it is the page's project — and cannot be changed from
  the composer.

  Submitting the first user message:
    - creates an agent_session with project_id = this project
    - routes into the existing chat pane with that session selected
    - cwd for the run = project_path
  Until the user submits, no session is created. Refreshing or closing the
  page is a no-op against the database.

  Right-side panels (Instructions, Scheduled, Context, Memory) shown in
  the reference screenshot are OUT OF SCOPE for the intermediate phase.

  Both Scene 2 and Scene 3 are RENDERED AS A FULL OVERLAY over the central
  pane. The sidebar stays visible. No internal tab is created. Driven by
  a single projectViewAtom: null | {mode:"index"} | {mode:"landing", projectId}.

  On first message submit (Scene 3):
    - the new agent_session is created with project_id set
    - selectedSessionIdAtom is set to that session
    - projectViewAtom is cleared
    - the chat pane takes the FULL central size; the middle "landing"
      pane collapses away in the same render

  Start from scratch (a):
    - location field defaults to <DEFAULT_PROJECTS_DIR>/<Name>
    - location updates live as the user types Name

    - on Create: if the chosen path does not exist, it is created (mkdir)

  Use an existing folder (b):
    - location field is empty + clicking it opens a dir picker immediately
    - on Create: the chosen path MUST exist; if it doesn't, creation errors

  "Instructions" and "Add files" fields in the reference screenshot are
  OUT OF SCOPE for intermediate.


INTERACTIONS
------------

• [+] New chat   → creates session with project_id = NULL  (General)
• [+] beside a project section → creates session with project_id = that project
• Drag a session row onto another section header → reassigns project_id    [LATER PHASE]
• Right-click a session row → "Move to project ▸" submenu                  [LATER PHASE]
• Click any session row → opens it in the chat pane (becomes the *selected* session)
• ● dot = session is currently running (is_active). Independent of selection.
• Selected session = background fill on its row.


REMOVED IN INTERMEDIATE PHASE
-----------------------------

• Recents section — SidebarRecentsSection and both recent atoms
  (recentFilesAtom, recentOutputsAtom) are deleted. Recent files/outputs
  no longer surface anywhere in the sidebar.
• Workspace switcher popover loses two actions:
    – "Publish to Store"
    – "+ Create new workspace"
  Workspaces are provisioned-only going forward. The switcher still
  shows the list, search, ⌘N shortcut hints, and delete.

LEGEND
------
[▢]  icon placeholder

○    inactive session (not currently running)

⋮    row overflow menu (rename / move / archive / delete)
⌄    expanded disclosure
⌘K   keyboard shortcut hint
+    inline create action
─    section divider
┌─┐  selected row or card hover
